# iPhone Share-menu Shortcuts

These credential-free Apple Shortcuts use native actions only. They require no paid developer account or third-party iPhone app.

- **Save to Cliptext** extracts supported post URLs from Share-sheet input, persists each request locally, and attempts delivery without opening the library.
- **Sync Cliptext** retries the local pending files.

Both must use the same parent folder under **On My iPhone**. They create a `Cliptext` child folder containing `pending`, `sent`, and `cliptext-connection.json`. Choose a local folder rather than iCloud Drive to keep links and credentials on the device. On the first run, paste the JSON connection settings generated by the Mac's Sharing setup. The submit-only token is stored in the local file, not in the Shortcut definition.

A network failure can display Apple's network error and stops that run. The request has already been saved; retry with Sync Cliptext or the next share. Acknowledged files move to `sent` only when both library ID and request ID match a receipt containing a job ID. They are not automatically deleted. The PWA cannot access this separate file outbox.

If connection settings change, move `cliptext-connection.json` out of that folder using Files and run the Shortcut again. Keep `pending` intact. See [iPhone setup](../docs/iphone.md) for installation and limits.

## Build

On a Mac with Apple's Shortcuts application:

```sh
python3 ios-shortcuts/generate.py
python3 -m unittest discover -s ios-shortcuts/tests -v
npm run build
```

The generator writes readable plist sources to `source/` and signed `.shortcut` files plus hashes to ignored `dist/`. It uses `/usr/bin/shortcuts sign --mode anyone`. The web build optionally includes only the two exact signed filenames in its dedicated PWA output; they are excluded from the offline shell cache. Signing may require running outside a restrictive development sandbox. Never inject a real hostname or token into these generic files.

Graph/schema checks and successful signing do not prove physical iPhone execution. The release manifest records `nativeRuntimeVerified:false` until device acceptance is completed. Test real TikTok share input, local folder permissions, request persistence, network failure, retry, and receipt archival on an iPhone before a public release.
